# 帆船赛现场控制和裁决台账

裁判组不再在成绩页逐条改秒数。系统按**比赛版本**管理成绩：比赛结束即冻结原始成绩，抗议裁决、重赛成绩和弃权一律通过**追加裁决**改变显示结果；未发布时晚到裁决自动重算，发布后只能生成更正版；发布只让最新版本成为正式成绩，旧版本全部可追溯。

## 核心规则

- **原始成绩冻结**：比赛结束时计时员提交到达秒数，生成 V1 原始版快照，之后任何人不能修改或覆盖。
- **裁决只追加（append-only ledger）**：抗议成立加罚 / 免罚、抗议驳回、重赛、计时更正、弃权（RET）都是新登记的裁决，带全局递增序号、提交方（计时员/裁判）和「基于序号」。
- **并发不覆盖**：后到的提交一律续接在已登记裁决之后继续计算——处罚按增量**累加**（+30 后再来 +20 = +50），重赛/计时更正只替换用时、不抹掉已登记处罚，弃权后不参与排名。
- **未发布自动重算**：晚到裁决触发新的重算草稿版本；旧草稿标记为「历史版本」但保留。
- **发布后只能更正**：正式版本快照不被改动，晚到裁决只入台账；显式「生成更正版」后再走发布流程。
- **单一正式版本**：发布时仅最新版本成为正式成绩，旧版本（含原始版）全部保留可追溯，版本行展示每条成绩依据了哪些裁决 `#seq`。
- **老数据升级**：旧的 `regatta-control-v1` 数据首次打开时自动迁移为 `regatta-ledger-v2`——旧秒数冻结为原始成绩，历史直接改的处罚转为追加裁决，旧时间线保留，迁移后可继续正常操作。
- **时间线**：记录冻结、每一条裁决、每次重算与每次发布（含版本号、裁决序号）。

## 技术栈

React 19、TypeScript、Vite、Ant Design、Redux Toolkit、RTK Query、React Router、React Hook Form、Zod、i18next。

纯领域计算见 `src/domain.ts`，reducer 见 `src/ledgerSlice.ts`，旧数据迁移见 `src/migration.ts`，数据结构见 `src/types.ts`。

```bash
npm install
npm run dev      # http://localhost:62024
npm run build
npm run verify   # 领域不变量 + reducer 端到端断言（共 20 项）
```

## 页面流程

1. **竞赛控制**：起航倒计时；「结束比赛并冻结」由计时员录入各船净用时，生成原始版；页内排行榜显示当前生效版本（正式版或待发布草稿）。
2. **成绩管理**：追加计时更正/重赛/弃权裁决（选择提交方角色），查看只追加的裁决台账、全部版本快照与「依据裁决」；发布后在此生成并发布更正版。
3. **抗议与申诉**：登记抗议 → 进入复核 → 成立加罚（输入加罚秒数，累加不覆盖）/ 成立免罚 / 驳回，裁决原子写入台账；右侧时间线展示裁决、重算与发布全过程。

数据使用 localStorage 持久化（`regatta-ledger-v2`），页头「重置演示」可恢复初始数据。
